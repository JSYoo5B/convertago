# 리플렉션 캐시 및 메시지 변환 벤치마크

Apple M3 Pro, darwin/arm64, Go 1.27.1, GOMAXPROCS=1. 2026-10-01에 커밋 `6e7adf5`를 측정했다. race 옵션 없이 각 항목을 3회 측정한 중앙값이다.

## 타입 메타데이터 캐시

각 항목을 독립된 프로세스에서 2,000,000회 실행했다. Cached는 이미 만들어진 타입 계획을 조회하고, Uncached는 매번 같은 구조체의 태그를 해석하고 구조를 검증한다. Uncached에는 캐시 삽입·삭제가 포함되지 않는다.

CPU 시간은 os.wait4가 반환한 user·system 시간의 합이다. 프로세스 시작, 벤치마크 준비, GC 비용을 포함하며, 경과 시간인 ns/op와 별도로 측정했다.

| 입력 | 캐시 | ns/op | CPU 초 / 200만 회 | B/op | allocs/op | 최대 RSS MiB |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Flat | Cached | 25.5 | 0.0546 | 0 | 0 | 6.72 |
| Flat | Uncached | 2,449.0 | 4.8307 | 5,224 | 27 | 11.33 |
| Nested | Cached | 25.1 | 0.0534 | 0 | 0 | 6.73 |
| Nested | Uncached | 3,279.0 | 6.4936 | 5,008 | 44 | 11.61 |

Flat의 타입 메타데이터 처리에서 캐시 조회의 CPU 비용은 반복 해석 대비 약 88.5배 작았다. 캐시 조회 자체의 추가 할당은 0 B/op, 0 allocs/op이었다.
Nested의 타입 메타데이터 처리에서 캐시 조회의 CPU 비용은 반복 해석 대비 약 121.6배 작았다. 캐시 조회 자체의 추가 할당은 0 B/op, 0 allocs/op이었다.

## 현재 값 읽기: Cold와 Warm

100ms씩 3회 측정했다. Cold는 해당 입력의 root 및 dynamic 타입 계획을 매번 지운 뒤 Fields를 호출한다. 삭제 비용은 타이머와 할당량 측정에서 제외한다. 타이머 중단·재개 비용이 프로세스 CPU 시간을 왜곡하므로, 이 표에서는 Go 벤치마크가 측정한 경과 시간과 할당량을 비교한다.

| 입력 | 캐시 | ns/op | B/op | allocs/op |
| --- | --- | ---: | ---: | ---: |
| Flat | Cold | 3,931.0 | 6,552 | 33 |
| Flat | Warm | 384.3 | 1,219 | 3 |
| Nested | Cold | 5,845.0 | 9,360 | 62 |
| Nested | Warm | 1,387.0 | 4,225 | 15 |
| Dynamic | Cold | 5,577.0 | 10,208 | 67 |
| Dynamic | Warm | 1,607.0 | 4,417 | 16 |

## 메신저별 전체 변환

각 항목을 독립된 프로세스에서 100,000회 실행했다. 세 메신저에 같은 입력을 사용한다. 변환 전 캐시를 준비하며, 값 읽기·조합·검증·네이티브 메시지 생성 비용을 포함한다. 호출자가 수행하는 JSON 직렬화는 제외하며, 변환기 내부의 직렬화는 포함한다. Dynamic은 Nested 입력을 any 필드로 감싼 형태로, 같은 내용을 출력한다.

| 메신저 | 입력 | ns/op | CPU 초 / 10만 회 | B/op | allocs/op | 최대 RSS MiB |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Kakaowork | Flat | 2,523.0 | 0.2534 | 3,488 | 46 | 12.09 |
| Kakaowork | Nested | 7,783.0 | 0.7745 | 11,056 | 123 | 12.62 |
| Kakaowork | Dynamic | 10,633.0 | 1.0582 | 12,456 | 143 | 12.83 |
| Slack | Flat | 2,870.0 | 0.2885 | 3,784 | 56 | 12.16 |
| Slack | Nested | 9,943.0 | 0.9890 | 12,808 | 153 | 12.75 |
| Slack | Dynamic | 13,081.0 | 1.3016 | 14,272 | 175 | 12.89 |
| GoogleChat | Flat | 5,523.0 | 0.5528 | 5,960 | 75 | 12.92 |
| GoogleChat | Nested | 16,884.0 | 1.6806 | 17,890 | 193 | 13.17 |
| GoogleChat | Dynamic | 20,070.0 | 1.9967 | 19,355 | 215 | 13.55 |

B/op와 allocs/op는 호출당 할당량이다. 캐시가 보관하는 메모리와 프로그램 전체의 상주 메모리 크기는 별개이며, 최대 RSS는 Go 런타임을 포함한 프로세스 전체의 최고값이다. 캐시 적중 후에도 현재 값을 읽고 메시지를 생성하는 할당은 발생한다.

전체 테스트, race를 적용한 벤치마크 1회 실행, go vet, git diff --check를 통과했다. 성능 수치는 이 환경의 측정 결과이며 테스트 통과 조건으로 사용하지 않는다.

각 실행의 원본 수치는 [measurements.csv](measurements.csv)에 기록했다. Fields 항목은 타이머 중단·재개 때문에 CPU와 RSS 열을 비워 두었다. 실행 방법은 [루트 README의 Benchmarks](../README.md#benchmarks)를 참고한다. 이 측정에서는 타입 계획은 200만 회, 메시지 변환은 10만 회를 사용했다.
